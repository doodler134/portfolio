# Portfolio — secure cloud version

Эта версия сохраняет портфолио в Supabase, а файлы в Storage держит **private**.
Публичный сайт получает только временные signed URLs (15 минут) через Edge Function.

## Что нужно сделать один раз

1. В Supabase открой **SQL Editor**.
2. Запусти `supabase.sql`.
   - Если Supabase покажет предупреждение про destructive operations — это нормально для этого setup-скрипта. Запускай его только в проекте этого портфолио.
3. В Supabase открой **Edge Functions → Create a new function**.
4. Назови функцию `portfolio-media-url`.
5. Вставь содержимое:
   `supabase/functions/portfolio-media-url/index.ts`
6. В настройках функции оставь JWT verification выключенным для этой функции, потому что она используется публичной частью сайта.
7. В `config.js` укажи **Project URL** и **Publishable key**.
8. Оставь `STORAGE_BUCKET` равным `portfolio-media`.
9. На GitHub Pages загрузи `index.html`, `config.js`, `.nojekyll` и остальные файлы проекта.

### Важно про ключи

`SUPABASE_PUBLISHABLE_KEY` **можно видеть в исходном коде**. Supabase прямо предназначает publishable key для браузерных приложений и публичного исходного кода.

**Никогда не добавляй в GitHub:**
- `sb_secret_...`
- `service_role`
- `.env` с секретами

Секретный ключ уже берётся Edge Function из секретов Supabase.

## Что изменилось с прошлой версии

- `portfolio-media` теперь private.
- Старый public-read policy для Storage удаляется.
- Картинки и фон не получают постоянные public URLs.
- Сайт получает временные signed URLs через Edge Function.
- Edge Function разрешает выдавать ссылки только на файлы, которые реально используются текущим портфолио.
- Загрузка/удаление файлов остаётся доступной только авторизованному редактору.

## Важное ограничение

Если изображение показывается человеку на сайте, его технически можно сохранить через браузер/скриншот. Никакая веб-архитектура не может сделать опубликованное изображение «невозможно скачать».

Private Storage защищает от постоянных публичных Storage URL и от случайного просмотра содержимого bucket.

## Обновление сайта

При следующих изменениях дизайна просто заменяй файлы сайта на GitHub. Данные портфолио и файлы в Supabase не удаляются.

`supabase.sql` повторно запускать без необходимости не нужно.
