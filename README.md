# Portfolio — cloud version

Статический сайт-портфолио без npm, React и сборки. Работает локально и готов для GitHub Pages.

## Что теперь есть

- выраженный 3D tilt карточек без свечения курсора;
- fullscreen просмотр и `← / →`;
- редактор;
- drag & drop перестановка постеров на ПК и touch-перетаскивание на телефоне;
- PNG/JPG/WEBP/GIF;
- кастомный фон, включая GIF;
- локальный кэш через IndexedDB/localStorage;
- облачная синхронизация между ПК и телефоном через Supabase;
- email/password авторизация только для редактора;
- публичный просмотр портфолио без авторизации;
- GitHub Pages ready;
- никаких npm-зависимостей для самого проекта.

## 1. Локальный запуск

Самый простой вариант: открыть `index.html`.

Для localhost:

```bash
python -m http.server 8000
```

Открыть `http://localhost:8000`.

Без настройки Supabase сайт остаётся полностью локальным.

## 2. Подключение облака

Используется Supabase. В папке лежат:

- `config.js` — сюда вставляются URL проекта и publishable key;
- `supabase.sql` — готовая схема базы, RLS и Storage policies.

### В Supabase

1. Создай бесплатный проект.
2. Открой SQL Editor.
3. Выполни весь `supabase.sql`.
4. В Authentication создай одного пользователя с email и паролем.
5. Отключи публичную регистрацию пользователей. Редактор должен быть единственным аккаунтом с правом записи.
6. Открой Settings → API Keys и возьми Project URL и publishable key.
7. Вставь их в `config.js`:

```js
window.PORTFOLIO_CONFIG = {
  SUPABASE_URL: 'https://YOUR-PROJECT.supabase.co',
  SUPABASE_PUBLISHABLE_KEY: 'YOUR-PUBLISHABLE-KEY',
  STORAGE_BUCKET: 'portfolio-media'
};
```

**Никогда не вставляй сюда `service_role` или другой secret key.** В браузере должен использоваться только publishable/anon key.

## 3. Как работает синхронизация

Публичный сайт читает одну запись `portfolio_state` и публичные файлы из bucket `portfolio-media`.

Редактор после входа может:

- загружать постеры;
- загружать фон;
- менять названия и описания;
- менять порядок;
- менять тему и параметры отображения;
- сохранять всё в облако.

Изображения хранятся в Storage, а не в базе. Это важно для больших файлов.

На каждом устройстве также остаётся локальный кэш. Если интернет временно пропал, уже загруженные данные продолжают отображаться.

## 4. GitHub Pages

Для GitHub Pages достаточно загрузить содержимое этой папки в репозиторий.

Важно: `index.html` и `config.js` должны лежать в корне публикуемой папки.

В Settings → Pages выбери публикацию из `main` / root.

После публикации сайт будет доступен с телефона по адресу GitHub Pages. Открываешь редактор, входишь под тем же аккаунтом — и получаешь тот же портфель.

## 5. Безопасность

- `config.js` может находиться в публичном репозитории: publishable/anon key не является service-role секретом.
- Запись в базу разрешена только авторизованному владельцу.
- Загрузка/изменение/удаление файлов разрешены только владельцу.
- Публично доступны только сами файлы портфолио и чтение опубликованного состояния.

## Важное ограничение

Если ты поменял портфолио локально без входа в редактор, эти изменения пока остаются только на этом устройстве. Для межустройственной синхронизации войди в редактор и нажми `Сохранить в облако`.
